## Implemented

- Schema v2 stores selected app plus each panel's typed kind, visibility, finite position,
  size, z-order, focus and pin state. It caps panel count and rejects duplicate IDs,
  invalid enums, invalid bounds, closed panels with z-order and multiple/non-visible focus.
- Schema v1 is accepted only through a deterministic v1→v2 migration; absent pin state
  becomes `false`. Unknown versions and malformed/oversized JSON fail closed.
- AES-256-CBC uses a random IV. HMAC-SHA-256 covers format/version/length/IV/ciphertext
  and is verified in fixed-time before decryption. Encryption and MAC use separate key
  halves from a random 64-byte installation key.
- The repository uses fixed file names under a caller-provided sandbox root and stages
  bytes before replace/move. Invalid candidates never replace live in-memory state.
- Restore replays the existing typed/versioned `PanelRegistry`; a rejected transition
  rejects the whole candidate.

## Limitation

The random key is a separate fixed file in the application sandbox. This protects against
casual plaintext inspection and detects tampering, but it is not iOS Keychain-backed and
is not claimed to resist a fully compromised device. A future key-provider replacement
can retain this schema/envelope/repository contract.
