## Implemented

- `PanelFactory` creates only the four allowlisted panel kinds and rejects duplicate
  active IDs or non-visible state.
- Each ID has at most one active `PanelView`. Closing/minimizing returns a view to its
  kind-specific pool and reopening reuses that instance.
- Each per-kind pool retains at most four inactive views; excess objects are destroyed.
  The registry itself is independently capped at eight panels.
- `PanelWorkspaceController` checks registry/view consistency before mutation and returns
  `ViewStateConflict` without version drift when external state mutation is detected.
- Views display their panel ID, use smaller text for long IDs, update cyan focus/pinned
  state from snapshots and consume a serialized material in the iOS fixture.
