# EV-S02-04 — Camera permission and lifecycle protocol

**Sprint / task:** S02 / T-S02-04  
**Date:** 2026-10-30  
**Current result:** PASS — deny, retry, Settings recovery, allow and
background/resume completed on the physical iPhone 11 without an application crash.

## Implemented boundary

- The iOS purpose string states that the camera is used only to scan a Cardboard viewer
  QR code and load optical parameters.
- The official Cardboard scanner owns QR capture; OmniLens does not retain camera frames.
- `CardboardScanGate` defers native scanner launch until the physical device reports
  `LandscapeLeft` or `LandscapeRight`, avoiding the reproduced portrait hit-test defect.
- `S02RuntimeProbe` records bounded lifecycle and XR state only. It does not store images,
  account data, device identifiers, precise location or raw media.

## Lifecycle evidence

The earlier physical scanner-return run recorded `focus_lost` and `background` at
145.355–145.356 s, followed by `focus_gained` at 148.335 s and `resume` at 148.351 s.
Subsequent 300-frame windows returned to approximately 33.33 ms average. Device Hub
visually confirmed stereo rendering after `Skip`.

The final sanitized collection is retained in `EV-S02-04-runtime.jsonl`. It contains a
fresh startup and one frame window after the permission sequence. The 36.998 ms average
includes a 716.406 ms startup outlier and is not used to replace the established stable
runtime result.

## Diagnostic limitation retained

`Application.HasUserAuthorization(UserAuthorization.WebCam)` logged
`camera_authorized=false` even when the app-specific Camera toggle was ON and the native
Cardboard scanner opened with the iOS privacy indicator. The Unity authorization API and
the native plugin do not expose the same observable permission state in this build.
Therefore the evidence uses the OS toggle and actual native scanner behavior as the
authority; the false Unity value is retained rather than rewritten or hidden.

## Portrait scanner defect reproduced and mitigated

Before the gate, launching the native scanner while the connected device reported
`portrait` rendered its landscape panel rotated 90 degrees with mismatched visible and
hit-test coordinates. The scanner was recovered without an application crash.
`CardboardScanGate` now permits launch only in physical landscape. Seven EditMode tests
cover the orientation-gating behavior, bringing the S02 suite to 27/27.
